## Fullstack Generation Agent — frontend project rules

This frontend is generated by the Fullstack Generation Agent. The `nextjs-skills` skill is the foundation: follow
its rules and its PR checklist. The rules below are additions; when they seem to conflict with the skill, these
win.

- **The plan is the contract.** `.bga/frontend-plan.json` (from `.bga/frontend-spec.json`) lists every route,
  component, data binding, form and test. Implement exactly the planned routes and component files; do not add
  routes, do not rename files.
- **Generator-owned files.** Never edit: `src/app/layout.tsx`, `src/app/providers.tsx`, `src/app/globals.css`,
  `src/config/site.ts`, `src/lib/**` (forms, form utilities, API client, generated operations, query keys, hooks),
  `src/mocks/**`, `src/content/**`, `src/components/ui/**` (shadcn), `src/components/layout/{Container,Stack,Grid,Section,ThemeToggle}.tsx`,
  `src/components/providers/**`, `src/hooks/use-mobile.ts`, `tests/**`, configuration files, `package.json` and
  the lock file. They are checked. You write `src/components/layout/SiteShell.tsx`, `src/components/sections/**`,
  `src/features/**` and the `page.tsx` files.
- **Pages.** Every `page.tsx` is a server component that exports `metadata` with `title` set to the page's SEO
  title from the plan, and renders the page's sections. Data-bound UI lives in client components (`"use client"`)
  under `src/features/<domain>/components/` or `src/components/sections/`. The root layout already renders
  `SiteShell`; the shell must render the page inside exactly one `<main>` element.
- **Data.** Only through the generated React Query hooks in `@/lib/api/queries` (named in the plan's `data[]`),
  with the parameters the plan gives. Never call `fetch`, never import `@/lib/api/client` or `@/lib/api/operations`
  from components, never hard-code an API URL. Show the section's loading, empty and error states.
- **Forms.** React Hook Form + `zodResolver` with the schema, values type and defaults from `@/lib/forms`; submit
  through the plan's mutation hook; number inputs use `register(name, { setValueAs: toNumber })` and the body goes
  through `compactValues` (both in `@/lib/form-utils`). Show the form's success toast (`sonner`) or navigate as
  the plan says.
- **Content.** Static text and collections come from `src/content/<collection>.json` (import the JSON) and the
  section `content` in the plan. Assets with `source: "placeholder"` render as a themed placeholder with the
  asset's alt text (`role="img"`), never an external image URL.
- **Style.** Only design tokens (`bg-primary`, `text-muted-foreground`, `border-border`…), never hex/rgb or
  arbitrary colour classes; layout with `Container`, `Stack`, `Grid`, `Section`. Named React imports only, `type`
  over `interface`, `T`-prefixed standalone types, `<Name>Props` for props. Logic over ~30 lines goes to the
  component's companion `use-*.ts` hook.
- **React.** Never call `setState` synchronously in a `useEffect` body. Compute derived values during render,
  initialise state lazily (`useState(() => ...)`), or reset state by giving a child component a `key`. Do not write
  `useMemo`, `useCallback` or `React.memo`: the React Compiler memoises. If you do write one, its dependency list
  must list every value the callback reads.
- **Links.** Internal links use `next/link` and the routes from the plan (`siteConfig.pages`); navigation comes
  from `siteConfig.navigation` and `siteConfig.footer`.
- **You cannot run commands.** Write code only; a separate system installs, type-checks, lints, builds and runs
  the tests (Vitest + Playwright on the mock API) and reports failures back to you.
